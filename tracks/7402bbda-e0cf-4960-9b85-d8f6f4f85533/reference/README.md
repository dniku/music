# Аудиореференсы

Аудиофайлы лежат локально в `reference/audio/`, а их содержимое хранится в
DVC. Полная запись зафиксирована отдельным `*.dvc`-указателем; минус является
выходом воспроизводимой стадии в соседних `dvc.yaml` и `dvc.lock`. Записи нужны
для проверки темпа, сильных долей, вокального ритма и структуры песни.
Машиночитаемые идентификаторы и SHA-256 хранятся в
[`recordings.json`](recordings.json).

Музыкальная сетка и общая структура обеих записей совпадают. Временные метки
контейнеров начинаются по-разному, поэтому выравнивать их следует по звуку, а
не по `start_time`.

## MusicBrainz

- исполнитель: [`1344ed95-93b9-4b48-b125-4e885117ab4b`](https://musicbrainz.org/artist/1344ed95-93b9-4b48-b125-4e885117ab4b);
- запись: [`7402bbda-e0cf-4960-9b85-d8f6f4f85533`](https://musicbrainz.org/recording/7402bbda-e0cf-4960-9b85-d8f6f4f85533);
- релиз: [`4deab243-b078-474e-9c3e-86da4e7d9768`](https://musicbrainz.org/release/4deab243-b078-474e-9c3e-86da4e7d9768);
- группа релизов: [`9e38b27b-1cb4-41df-9628-15142d8099e0`](https://musicbrainz.org/release-group/9e38b27b-1cb4-41df-9628-15142d8099e0);
- трек релиза: [`1fa0a485-baa8-431b-b776-d64670f1a2f9`](https://musicbrainz.org/track/1fa0a485-baa8-431b-b776-d64670f1a2f9).

Совпадение полной записи подтверждается исполнителем, названием, 2011 годом, номером трека 3 и длительностью около 5:35. В MusicBrainz у записи пока нет ISRC и связи с сущностью Work.

Минусу не присваивается MBID полной записи: отдельный микс считается отдельной Recording. До появления собственной записи в MusicBrainz его точным идентификатором служит SHA-256, а MBID полной версии записан только как связанный музыкальный референс.

Полная запись сохраняется в переданном пользователем виде. Минус хранится как
оригинальный WebM-поток YouTube: скачивание не перекодирует звук. Для медиатеки
следует тегировать копии из данных `recordings.json`, чтобы не менять
зафиксированные SHA-256 референсов.

Минус воспроизводится из корня репозитория:

```console
nix run .#dvc -- repro tracks/7402bbda-e0cf-4960-9b85-d8f6f4f85533/dvc.yaml:fetch-instrumental-reference
```

`dvc.lock` фиксирует хеши зависимостей и результата, а `flake.lock` того же
Git-коммита — версии yt-dlp и остальных инструментов. Стадия скачивания
дополнительно проверяет ожидаемый SHA-256 до принятия файла.

Прежний пользовательский Ogg Opus (`SHA-256 6774e9f2…307f7a4`) был заменён
только после проверки эквивалентности: lossless-remux нового WebM в Ogg даёт
те же 16 788 Opus-пакетов и побитно тот же декодированный PCM
(`SHA-256 f9422d56…ae893`). Старые байты и DVC-указатель остаются доступны в
истории Git/DVC.

Оригинальный фрагмент раннего соло `0:58.80–1:10.80` воспроизводимо
извлекается из полной записи в `build/`:

```console
nix run .#dvc -- repro tracks/7402bbda-e0cf-4960-9b85-d8f6f4f85533/dvc.yaml:extract-early-solo-reference
```

Полная запись была передана пользователем напрямую; её предшествующий URL и
команды скачивания или перекодирования неизвестны. Источник минуса подтверждён
и воспроизводимо зафиксирован описанной выше DVC-стадией.
