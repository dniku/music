# Аудиореференсы

Локальное аудио лежит в `reference/audio/`, а его содержимое хранится в
DVC-кеше. Идентичность, хеш и внешний источник зафиксированы в
[`recordings.json`](recordings.json); точная команда получения, зависимости и
выход находятся в соседних `dvc.yaml` и `dvc.lock`.

| Файл | Источник | Длительность | SHA-256 |
| --- | --- | ---: | --- |
| `youtube-nDxJJ_aEt2g.webm` | [YouTube `nDxJJ_aEt2g`](https://www.youtube.com/watch?v=nDxJJ_aEt2g), формат 251 Opus без перекодирования | 199,541 с | `e5c03bed…d92f30` |

Референс воспроизводится командой из корня репозитория:

```console
nix run .#dvc -- repro tracks/e889154d-ae2d-43f0-bd2d-df87d068c0f3/dvc.yaml:fetch-reference
```

Соло занимает диапазон `2:22.70–2:33.60` (`142,7–153,6` с). Отдельный MP3 для
прослушивания создаётся так:

```console
nix run .#dvc -- repro tracks/e889154d-ae2d-43f0-bd2d-df87d068c0f3/dvc.yaml:extract-solo-reference
```

`dvc.lock` фиксирует хеши зависимостей и результатов, а `flake.lock` того же
Git-коммита закрепляет версии yt-dlp, FFmpeg и других инструментов. Стадия
скачивания дополнительно проверяет ожидаемый SHA-256 до принятия файла.

Длительность YouTube-аудио на 10,441 с больше длительности связанной записи в
MusicBrainz (`189,1` с). Поэтому оно пока помечено как связанный, но не
тождественный вариант: название и исполнитель сами по себе не доказывают
совпадение конкретной Recording.
