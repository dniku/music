# Lost in Space — восстановление piano roll

Источник: [Alejandro Ríos Pianista, YouTube _-DEer9afE0](https://www.youtube.com/watch?v=_-DEer9afE0),
формат 299 (1920×1080, 60 fps, без аудио). Его SHA-256, автор и дата записаны
в `../reference/recordings.json`; сам файл хранится через DVC, не в Git.
Это другая аранжировка, не запись Avantasia и не замена нашего `score.ly`.

## Метод и ограничения

`recover.py` рассчитан только на этот проверенный по SHA-256 ролик, а не на
произвольные видео. Он использует Python standard library и FFmpeg, без ML.

- Фиксированная клавиатура: 88 клавиш A0–C8, 52 белые на ширину 1920 px.
  Синие прямоугольники — левая рука, зелёные — правая. Координаты чёрных
  клавиш откалиброваны по кадрам. Определяется центр целого прямоугольника:
  проверка отдельных пикселей ошибочно принимает широкую белую ноту за
  соседнюю чёрную.
- Две горизонтальные линии (y=300 и y=500) независимо дают по 1395 нот.
  Строго проверяются все расхождения: первая A1 закрыта начальной анимацией
  на верхней линии; две настоящие ноты снизу перекрывают частицы; ещё одна
  частица снизу похожа на C7. После этих явно записанных поправок — 1396 нот
  (843 в левой руке, 553 в правой).
- По кадровым интервалам сетка равна 120 BPM: четверть — 30 кадров,
  восьмая — 15, триольная восьмая — 10. Единица таблицы событий — 1/12
  четверти; она сохраняет и триоли, и шестнадцатые. Первая нота звучит на
  0:05.70 видео; первый MIDI-такт начинается с неё, без начальной тишины.
- Длина прямоугольников и отдельно подсветка клавиш указывают на короткое
  нажатие около 7–8 кадров, то есть шестнадцатую (0,125 s). Она сохранена
  буквально, с паузами до следующего события. Триольные участки поэтому
  выглядят необычно: шестнадцатая с точкой плюс пауза тридцать второй внутри
  триоли. Это не восстановление исполнительского легато или педали.
- Размер 4/4, границы тактов, энгармонические написания, ключевые знаки,
  октавные линии и временные метки — редакционное оформление. Ключевые
  знаки выбраны по набору высот, а не прочитаны из MIDI-метаданных.
  Громкость всех MIDI-нот одинаковая; динамика, педаль, аппликатура и
  авторские штрихи неизвестны. Результат следует считать черновиком.

## Воспроизведение

Из корня репозитория:

```sh
nix run .#dvc -- repro tracks/b0d93aa9-c69d-4b88-8432-1588eea622fc/dvc.yaml:render-piano-roll-audition
```

Цепочка DVC: загрузка → извлечение событий/нот → PDF/MIDI → MP3. Неизменённые
стадии пропускаются. Вместо повторной загрузки с YouTube можно восстановить
точный видеофайл из DVC remote. Если YouTube перекодирует поток, проверка
SHA-256 остановит извлечение: новая калибровка не применяется молча.

Команды и хэши зависимостей находятся рядом в `../dvc.yaml`/`../dvc.lock`,
версии инструментов берутся из `flake.lock`. При сборке извлекателя Nix
обязательно запускает Ruff format/check, Pyrefly и синтетические unit-тесты.
`../piano-roll.ily` — генерируемый, но сохраняемый в Git результат, поэтому
PDF и MIDI можно собрать без видео, сети и повторного анализа:

```sh
nix run .#render-lost-in-space-piano-roll
nix run .#render-midi-audition -- \
  build/avantasia--lost-in-space/piano-roll.midi \
  build/avantasia--lost-in-space/piano-roll.mp3
```

Результат находится в `build/avantasia--lost-in-space/piano-roll.{pdf,midi,mp3}`;
`piano-roll-events.json` содержит точные извлечённые высоты и моменты нажатий
для независимой проверки MIDI. Основной PDF на Pages пока остаётся прежним.
